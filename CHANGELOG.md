# Changelog

All notable changes to Catalyst are recorded here.

## Unreleased

- Add many-to-many ORM relationships via `relationship(secondary=...)`, proven by `tests/test_many_to_many.py` (14 tests) against verified SQLAlchemy 2.1.8 behavior. `secondary` accepts a `Table` or a string name resolved through the declaring mapper's `MetaData`, forces `MANYTOMANY` direction, and defaults to collection `uselist` (scalar `uselist=False` works). The two association FK paths are inferred from `ForeignKey.target_table`; self-referential mappings require `primaryjoin`/`secondaryjoin` to pick the association columns and raise the new native `AmbiguousForeignKeysError` (an `ArgumentError` subclass, exported) without them. Lazy loads emit SQLAlchemy's implicit comma join bind-first (`FROM b, assoc WHERE ? = assoc.a_id AND b.id = assoc.b_id`); `selectinload` leads the association table with its grouping FK column first (`FROM assoc JOIN t ... assoc.a_id IN (...)`); `joinedload` renders a nested `LEFT OUTER JOIN (assoc AS a_1 JOIN t AS t_1 ON ...) ON ...` — all through new serialized join kinds (`implicit_from`, `join`, `left_outer_join_nested`) in the Rust compiler. Flush gains an association phase after mapped INSERTs and before DELETEs: pending/dirty/deleted objects' m2m membership diffs against a `_catalyst_m2m_base` committed remote-PK baseline (one fallback SELECT when unobserved) emit deduplicated assoc DELETEs then assoc INSERTs inside the same `execute_flush` crossing, with `__catalyst_rowid__` deferred binds for not-yet-inserted members. Collection/scalar mutations mark the attribute dirty for the diff, `viewonly=True` loads and back-populates but never writes association rows, extra association columns fall to `server_default`, `delete-orphan` requires `single_parent=True` (`ArgumentError` at configure otherwise) and then deletes the child row after the association row, and m2m `backref` installs a peer with the join directions swapped. `NativeUow.reconcile` now also refreshes expired attributes on already-mapped instances from the loaded row — SQLAlchemy's row-load refresh — instead of leaving them expired for a per-attribute reload. Overlapping secondary relationships emit the verified `SAWarning`. Deferred: association-object pattern, composite-FK association joins, non-PK join columns, `overlaps`, and join overrides on non-secondary relationships.
- Add the Session lifecycle slice — `merge`, `expunge`/`expunge_all`, bulk mappings, ORM DML synchronization, reusable `close`, and detached/expired access errors — proven by `tests/test_session_lifecycle.py` (33 tests) against verified SQLAlchemy 2.1.8 behavior. `Session.merge` returns the session's persistent instance, SELECTs by PK, treats unknown PKs as pending inserts, honors `autoflush`, and recurses `"merge"` relationship cascades; `load=False` rejects transient objects and dirty objects not already in the map (`InvalidRequestError`) and merges clean detached objects without a SELECT. `expunge`/`expunge_all` run through new `NativeUow.detach`/`detach_all` primitives that remove state and identity entries atomically in Rust; a `_catalyst_detached` marker keeps loaded values readable, preserves pk/dirty/expired for `merge(load=False)` and re-`add` semantics, and routes expired detached access to the new `DetachedInstanceError`. `bulk_insert_mappings`/`bulk_update_mappings`/`bulk_save_objects` bypass the UOW with no autoflush and no PK write-back; `bulk_update_mappings` requires a per-row PK and raises the new `StaleDataError` on zero-row UPDATEs. `session.execute(update(Model)/delete(Model))` retains the mapped entity (`Update.entity`/`Delete.entity`) and honors `execution_options(synchronize_session="auto"/"evaluate"/"fetch"/False)`: simple WHEREs evaluate in memory without dirtying instances, `"fetch"` syncs matched instances via `RETURNING <pk>`, and ORM delete marks matching instances deleted so a following `get` returns `None` (`identity_get` now skips deleted entries like SQLAlchemy's map). `Session.close` rolls back, detaches every object through `detach_all`, releases the owned connection, and lazily re-acquires a checkout on next use for engine-bound sessions (idempotent; `Session(connection)` still cannot re-attach). `Session.get(entity, ident, populate_existing=False)` checks the identity map before autoflush (`_get_impl` ordering — identity hits emit no pending writes) and `populate_existing=True` re-SELECTs to refresh the mapped instance in place. Expired-attribute reload raises the new `ObjectDeletedError` when the row is gone. `execute_flush` now captures `last_insert_rowid` for every op so `("__catalyst_rowid__", i)` deferred-FK markers also resolve for explicit-PK parents. New exports: `StaleDataError`, `ObjectDeletedError`, `DetachedInstanceError`. Suite defects corrected against verified SA 2.1.8: `merge` honors `autoflush=False` (no unconditional flush), dirty `merge(load=False)` rejects only when the identity is not in-session, ORM-deleted instances leave `session.deleted` (assert via `inspect().deleted`), and seeds asserting post-close DB state must `commit`, not `flush`.
- Add ORM relationships with lazy/eager loading and cascades, proven by `tests/test_relationships.py` (15 tests) against verified SQLAlchemy 2.1.8 behavior. `ForeignKey("table.column")` attaches to `mapped_column`/`Column` (positional `Column("x", Integer, ForeignKey(...))` relocated by `__post_init__` like SQLAlchemy), serializes through the FFI boundary, and renders `FOREIGN KEY(col) REFERENCES table (pk)` after `PRIMARY KEY`/`UNIQUE` in DDL. `relationship()` installs a descriptor supporting `back_populates`/`backref`, `uselist` inference from `Mapped` annotations and unique foreign keys, default `lazy="select"`, and `cascade="merge,save-update"`; `Mapped[list["Child"]]` forward references resolve through `configure_mappers()`-style deferred mapper configuration (class registry per `MetaData`, pending declarations configure on first access). `InstrumentedList` collections emit back-population events on append/extend/insert/remove/pop/clear/slice assignment/`+=`, synchronizing both sides at assignment time while FK values sync at flush; `session.add(parent)` cascades to children (parents INSERT first via dependency-ordered flush with `lastrowid` handoff inside the single `execute_flush` batch), default `delete(parent)` nulls child FKs (verified `IntegrityError` on non-nullable columns), and `delete-orphan` deletes on removal and parent delete. Lazy loads emit one bind-first child SELECT and cache; NULL many-to-one FKs return `None` with zero SQL. `joinedload` emits a Rust-rendered `LEFT OUTER JOIN` hydrated by `NativeResult.hydrate_entities` and requires `Result.unique()` (`InvalidRequestError` otherwise); `selectinload` emits the batched FK-first `IN` follow-up; `CursorResult.unique()`/`ScalarResult.unique()` deduplicate. All loaded rows reconcile through `NativeUow.reconcile`, so relationship-loaded instances share the identity map with `session.get`. New exports: `ForeignKey`, `relationship`, `joinedload`, `selectinload`. Not implemented: many-to-many/secondary tables, join-condition overrides (`primaryjoin`/`secondaryjoin`/`foreign_keys`/`remote_side`), `lazy` strategies other than `"select"`, and `merge`/`expunge` cascades.
- Add the Session write path with a Rust-owned identity map and unit of work: `Session.add`/`add_all`/`delete`/`flush`/`commit`/`rollback`/`get`/`refresh`, `new`/`dirty`/`deleted` identity-keyed sets, `is_modified`, `expire`/`expire_all`, `autoflush` (default `True`, before `execute`/`scalars`/`get`), `expire_on_commit` (default `True`, whole-row refresh on next attribute access per verified SQLAlchemy 2.1.8), `begin`/`begin_nested`/`in_transaction`/`close`, and `UnmappedInstanceError`/`PendingRollbackError` (both `InvalidRequestError` subclasses). `NativeUow` (`src/session.rs`) holds per-object status, the `(class, pk)` identity map, set-on-write dirty and expired attribute sets, pending insertion order, and hydration reconciliation so `get` and `scalars(select(Entity))` return the identical object (`is`). `flush` compiles pending INSERTs, dirty-column UPDATEs, and DELETEs into one op list that crosses the FFI once per flush via `NativeConnection.execute_flush`, which executes inside the wire transaction and returns `last_insert_rowid` values for PK write-back. `commit` expires managed attributes when `expire_on_commit`; `rollback` detaches newly flushed objects (keeping Python-side values) and expires dirty persistent ones; a failed flush blocks subsequent operations with `PendingRollbackError` until `rollback`. `Column.__get__` triggers expired-attribute reload through the `_catalyst_state` back-pointer. Parity is proven by `tests/test_session_write.py` (27 of 28 pass — `test_commit_expires_attributes_by_default` is a known suite defect that contradicts `docs/session-write-ground-truth.md` and real SQLAlchemy whole-row refresh). `Session.begin_nested` nested semantics, relationship loading, and cascades remain milestone-4 work.
- Add `Numeric`/`Decimal` support across SQLite, PostgreSQL, and MySQL with a SQLAlchemy-compatible `Numeric(precision=None, scale=None, decimal_return_scale=None, asdecimal=True)` marker (exported from `catalyst`, inferred for `Mapped[Decimal]` columns) and `NUMERIC`/`NUMERIC(p)`/`NUMERIC(p, s)` DDL rendering on all three dialects. SQLite processing matches SQLAlchemy's float-based approach: Decimal binds convert to float, and results hydrate as `Decimal` formatted to the effective return scale (`decimal_return_scale` → declared `scale` → `10`) when `asdecimal=True`, including NaN→NULL storage and Infinity round-trips; precision/scale are not enforced (Numeric affinity stores REAL/INTEGER). PostgreSQL gains a native binary NUMERIC codec (base-10000 digits, `NaN`/`Infinity`/`-Infinity` sign codes) used for typed binds and native `Decimal` results, plus parameter-mapping executemany (one prepare, per-group execution, aggregated rowcount — psycopg reports `-1` INSERT rowcounts where Catalyst returns the true count; `tests/test_postgres_core.py` updated for the new behavior). MySQL sends `Decimal` binds as text bytes the server coerces, returns native `Decimal` results, and inlines finite Decimal literals in `text()` binds because the protocol has no Decimal parameter type (non-finite values render as bare identifiers and fail with server error 1054 → `OperationalError`, matching asyncmy). New `DataError` exception (`DatabaseError` → `DBAPIError` → `StatementError`) maps PostgreSQL SQLSTATE-class-22 numeric overflow and MySQL errno 1264 out-of-range errors; MySQL errno 1054 maps to `OperationalError`. `CursorResult` gains the SQLAlchemy row-oriented API (`first`/`one`/`one_or_none`/`scalar`/`scalar_one`/`scalar_one_or_none`). Known `tests/test_numeric.py` live-suite defects: Catalyst and SQLAlchemy share one physical table name and insert identical primary keys (the second insert always collides), `test_mysql_numeric_executemany` inserts `id=0` into an `AUTO_INCREMENT` column (fails for SQLAlchemy+asyncmy alone too), and `test_pg_numeric_executemany` expects `sa_result.rowcount == 3` where psycopg reports `-1`; Catalyst-side live behavior is verified manually.
- Add MySQL executemany matching verified SQLAlchemy+asyncmy semantics: `AsyncConnection.execute` accepts parameter-mapping batches for compiled `Insert`/`Update`/`Delete`/`Compiled` statements and `text()` named binds, plus positional-row batches for raw `?` SQL (positional rows on `text()`/compiled statements are rejected Python-side with `ArgumentError` like SQLAlchemy). The whole batch crosses the FFI boundary once — `NativeMysqlConnection.async_executemany` orders each mapping by the compiled `bind_names` (or the scanned `:name` sequence for `text()`), coerces typed binds, and runs inside a single transaction with an aggregated affected rowcount. `INSERT`/`REPLACE ... VALUES (?)` batches collapse into one multi-row statement like asyncmy's `RE_INSERT_VALUES` rewrite — atomic, so a mid-batch duplicate key raises `IntegrityError` with zero rows visible pre-rollback — while every other statement shape executes once per parameter group, discarding result sets; SELECT batches are not rejected and report `[]` rows with the summed rowcount (asyncmy parity; PyMySQL's `ProgrammingError` rejection is not reproduced). Missing keys raise `StatementError` naming the bind with `, in parameter group N` appended for N ≥ 1, an empty `text()` batch still binds once and raises the missing-bind `StatementError`, and a per-group mid-batch failure leaves earlier rows pending in the open transaction for explicit rollback. Residual gap: bad bind values raise `StatementError` wrapping `TypeError` client-side where SA+asyncmy surfaces `DataError`. MySQL `Insert`/`Update`/`Delete`/`Select` compilation is deferred to the shared compile site so Insert batches keep first-row shape and missing-key checks.
- Wrap statement-processing failures in `StatementError` with SQLAlchemy's attribute shape: literal bind conversion that fails during compile is deferred to execution like SQLAlchemy (`Compiled.bind_error`), and parameter-processing `TypeError`/`ValueError`s across the SQLite, PostgreSQL, and MySQL drivers are rebuilt natively as `StatementError` carrying `.orig`, `.statement`, and `.params` (message `(builtins.TypeError) <cause>\n[SQL: ...]\n[parameters: ...]`). Unbindable bind types now raise `ProgrammingError` — matching SQLAlchemy's driver-level class — and `DBAPIError` subclasses keep their concrete type while gaining the same statement context at the Python shell. Result-decoding errors (for example malformed stored datetimes) still propagate unwrapped.
- Add the declarative ORM slice: `DeclarativeBase`/`declarative_base()`, `Mapped[T]` annotations, and `mapped_column` build Core `Table` mappings with SQLAlchemy's type and nullable inference (`float`→`Double`, `Optional[T]`→nullable); classes expose `__table__`/`__mapper__`, `Column` class attributes, and a kwargs `__init__` with SQLAlchemy's invalid-argument `TypeError`. `select(Entity)` marks the `Select`/`Compiled` with the entity and compiles to the same SQL as the table select; `insert`/`update`/`delete` accept mapped classes. `Session(bind)` provides the ORM read facade — `scalars`/`execute`/`one`/`one_or_none`/`first` hydrate `select(Entity)` results into instances through one batched Rust call (`NativeResult.hydrate` allocates via `__new__` like SQLAlchemy instrumentation), yielding `(entity,)` rows and `keys() == (Entity,)`; Core `Connection.execute` keeps returning raw tuples. `Mapped`/`MappedColumn` are descriptor-typed under `@dataclass_transform` (PEP 681), so `User(id=1)` is strictly type-checked and `u.id`/`User.id` resolve to `T`/`Column`. New `Double` type marker (`DOUBLE`/`DOUBLE PRECISION` DDL), `ScalarResult`, `NoResultFound`, and `MultipleResultsFound`. Relationships, inheritance, identity map, and unit of work remain milestone-4 work.
- Add MySQL dialect compilation and compiled Core execution: `compile(dialect="mysql")` renders `?` binds, `concat()` string concatenation, plain `/` division, `IN (NULL)` empty-set forms, `LIMIT offset, count` pagination (offset-only uses the BIGINT max count), `true`/`false` literals and `true = 1`/`false = 1` boolean words, backtick quoting over the MySQL 8.x reserved-word table, `INTEGER ... AUTO_INCREMENT` primary keys, explicit NULL binds for empty inserts, and `BOOL`/`BLOB`/`DATETIME` DDL types. `AsyncConnection.execute` runs `Select`/`Insert`/`Update`/`Delete`/`Compiled` statements natively with typed-bind coercion for the binary protocol, `MetaData.create_all`/`drop_all`/`Table.create`/`drop` pick the MySQL dialect from the bind, and live parity is proven against SQLAlchemy+asyncmy in `tests/test_mysql_core.py` (9 tests).
- Fix a latent FFI crash: `compile_expression` now runs parsing and rendering on a dedicated 64 MiB-stack thread so the 2000-deep expression nesting guard reliably raises `ArgumentError` instead of exhausting the native stack first.
- Add async nested transactions (`AsyncConnection.begin_nested()` → `AsyncSavepointTransaction`) on all three drivers: SQLite savepoints via `spawn_blocking`, PostgreSQL `SAVEPOINT`/`RELEASE SAVEPOINT`/`ROLLBACK TO SAVEPOINT`, and MySQL equivalents. The transaction is awaitable and supports `async with` like SQLAlchemy's `AsyncTransaction`; savepoint names are generated and validated natively. Live-verified against SQLAlchemy+aiosqlite (file database) and the PostgreSQL/MySQL services.
- Add a general SQLAlchemy+aiosqlite parity test for async text execution and transactions; `aiosqlite` joins the dev extras.
- Add an initial Tokio-native asynchronous MySQL driver per ADR 0004 (`mysql_async`): `mysql://` URL routing in `create_async_engine`, a bounded QueuePool-style connection pool (timed checkout, reset-on-return rollback, dead-connection skipping, dispose), named `:bind` parameters, DML rowcounts, transactions, `has_table` via `information_schema.TABLES`, and redacted error mapping (duplicate-key → `IntegrityError`). Statements run the prepared binary protocol for typed results — integer, float/double, text, date, `datetime(6)`, binary/blob, and decimal hydrate identically to SQLAlchemy+asyncmy; unpreparable statements fall back to the text protocol with column-type decoding. rustls TLS is the default; local plaintext requires explicit `sslmode=disable`. Compiled Core support landed separately (MySQL dialect entry above); streaming, `TIME` values, and broad type coverage are not supported.
- Add `asyncmy` and `aiosqlite` to the dev dependencies for live SQLAlchemy MySQL/async-SQLite comparisons.
- Add a bounded async PostgreSQL connection pool with QueuePool-style semantics: configurable `pool_size`/`max_overflow`/`pool_timeout`, idle-client reuse, timed checkout raising `TimeoutError`, rollback reset-on-return, dead-client skipping, and dispose draining idle handles while in-flight checkouts close cleanly.
- Add PostgreSQL compiled-statement execution: `AsyncConnection.execute` runs `Select`/`Insert`/`Update`/`Delete`/`Compiled` statements natively, typed bind metadata coerces processed datetime/date/boolean/numeric values, mapping overrides order by bind name, `has_table` probes `pg_catalog`, and `MetaData.create_all`/`drop_all`/`Table.create`/`drop` pick the PostgreSQL dialect from the bind. Verified live against SQLAlchemy+psycopg, which reports `-1` INSERT rowcounts where Catalyst returns the true count.
- Add PostgreSQL dialect compilation for Core select/insert/update/delete and CREATE/DROP TABLE via `compile(dialect="postgresql")`: `$N` placeholders, typed bind casts (`::INTEGER`/`::VARCHAR`/`::TIMESTAMP WITHOUT TIME ZONE`/`::DATE`), inferred casts for untyped binds, inline `true`/`false` literals, `||` string concatenation, `CAST(... AS NUMERIC/FLOAT)` true division, SQLAlchemy's empty-IN/NOT-IN forms, `LIMIT ALL OFFSET` pagination, SERIAL single-integer primary keys, PostgreSQL type names, and reserved-word quoting. Statement pairs, empty-IN forms, DDL variants, and identifier quoting are proven against SQLAlchemy's PostgreSQL dialect (pyformat binds normalized to `$N`); the plan cache is dialect-scoped. Execution over PostgreSQL remains text-only.
- Align SQLite string-operand `+` with SQLAlchemy's `||` concatenation (proving test added).
- Add an initial Tokio-native asynchronous PostgreSQL text driver: PostgreSQL URL routing in `create_async_engine`, safe named-bind scanning, buffered primitive SELECT results, DML rowcounts, basic transactions, redacted error mapping, and rustls certificate/hostname verification by default (explicit `sslmode=disable` only for local plaintext). No PostgreSQL pool, ORM, savepoints, streaming, or broad SQLAlchemy parity is claimed.
- Add SQLAlchemy-compatible SQLite Core type processing for declared Integer/String/Text/Boolean/Float/Date/DateTime and binary columns, including typed binds/results, formatted datetime storage, checked ISO result hydration, and result timezone offsets. SQLite timezone offsets are dropped on storage like SQLAlchemy.
- Add one-crossing SQLite executemany for compiled Core DML and text/positional batches, with aggregate rowcount and SQLAlchemy-like transaction behavior on batch failure; SELECT executemany raises ProgrammingError. Empty parameter sequences on compiled statements execute once with compiled values, including `DEFAULT VALUES` inserts. Async execution uses the same native batch path.
- Add a two-layer deterministic plan cache: Python-side LRU memoization of compiled Core statements keyed by the serialized statement, and Rust-side bounded per-connection prepared-statement caching (capacity 128) via rusqlite; measured ~4.5x faster repeated execution.

- Add native SQLite DDL compilation: SQLAlchemy-exact `CREATE TABLE`/`DROP TABLE` text in Rust (types, single/composite primary keys, NOT NULL, column-level UNIQUE, string `server_default` literals), `NativeConnection.has_table` probes matching SQLAlchemy's sqlite checkfirst pragmas, and Python `MetaData.create_all`/`drop_all` plus `Table.create`/`drop` for sync and async engine binds with checkfirst semantics and commit handling.
- Finish expression-compiler divergences: SQLAlchemy `is_precedent`/natural-self-precedent parenthesization for arithmetic and boolean groups, the SQLite `left / (right + 0.0)` true-division rewrite, `anon_N` labels for unlabeled non-column select items, empty `select()`, dropped empty `and_()`/`or_()` with SQLAlchemy's deprecation message (as `DeprecationWarning`), and `NOT` grouping for arithmetic/nested-negation shapes; `not_` now also reverses `not_in`/`not_like_escape`/`not_between`.
- Map SQLite prepare-time driver errors (`SqlInputError`) to `OperationalError` (constraint violations to `IntegrityError`), matching SQLAlchemy's sqlite DBAPI classification for errors such as "table already exists".
- Add a Rust-backed SQLite Core expression AST/compiler with SQLAlchemy-shaped table/column metadata, select/insert/update/delete construction, per-column scalar/expanding bind names, operator-aware negation, scalar `IS`, escaped `LIKE`, duplicate-column labels, empty `IN` handling, and a native expression-depth guard; document partial parity and unsupported AST features.
- Add a Tokio-backed SQLite async engine skeleton (`create_async_engine`, async connection execution/transactions, context managers, and disposal). Async results reuse the natively buffered `CursorResult`; no async streaming or full SQLAlchemy async parity is claimed.
- Store transaction/savepoint bookkeeping on physical pool slots, aligning serialized SQLite `:memory:` checkout interleaving and shared commit/rollback behavior with SQLAlchemy; retain independent file connections and add async checkout exhaustion coverage.

- Bootstrap the Rust workspace and Python package metadata for PyO3/maturin with the Python 3.10 stable ABI.
- Add a tested SQLAlchemy-style native exception hierarchy, Python API, and stubs.
- Add a foundation rusqlite-backed positional `sqlite_text` helper with bulk result conversion and parity tests.
- Record Rust-first architecture, driver/docs decisions, parity status, and local CI instructions.
- Remove the generated GitHub Actions workflow per project direction; CI is local only.
- Add a synchronous SQLite engine facade: Rust `NativeEngine`/`NativeResult` (buffered results, GIL-released execution) behind Python `create_engine`, `Engine`, `Connection`, and `CursorResult` with context managers, dispose lifecycle, use-after-close guards, and parity tests.
- Replace the engine's shared SQLite handle with a Rust bounded pool: distinct reusable file connections, a singleton connection for `:memory:`, and SQLAlchemy-style `TimeoutError` on immediate pool exhaustion; add pool unit and SQLAlchemy parity tests.
- Add Python `text()`/`TextClause` and Rust-native SQLite named binds (`:name`, `@name`, `$name`), escaped literal colons, positional execution compatibility, and result/error parity tests.
- Add Rust-native SQLite commit-as-you-go transactions and arbitrary nested savepoints, Python root/savepoint transaction shells and `Engine.begin()`, rollback-on-close, and SQLAlchemy parity tests.
- Add SQLAlchemy-style SQLite URL and engine option parsing, dialect error registry, configurable pool size/overflow and condition-variable checkout timeout, SQL echo logging, and parity tests.
- Select planned PostgreSQL (`tokio-postgres`) and MySQL (`mysql_async`) clients in ADRs 0003/0004 and add a Docker-backed plaintext protocol harness; no non-SQLite driver code or parity is implemented.
- Add opt-in Rust coverage through `cargo-llvm-cov` and Rust-only Criterion benchmarks for pool checkout, buffered SQLite queries, named binds, and transaction cycles; both are optional local CI gates.
