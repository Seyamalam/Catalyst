# Changelog

All notable changes to Catalyst are recorded here.

## Unreleased

- Add async nested transactions (`AsyncConnection.begin_nested()` → `AsyncSavepointTransaction`) on all three drivers: SQLite savepoints via `spawn_blocking`, PostgreSQL `SAVEPOINT`/`RELEASE SAVEPOINT`/`ROLLBACK TO SAVEPOINT`, and MySQL equivalents. The transaction is awaitable and supports `async with` like SQLAlchemy's `AsyncTransaction`; savepoint names are generated and validated natively. Live-verified against SQLAlchemy+aiosqlite (file database) and the PostgreSQL/MySQL services.
- Add a general SQLAlchemy+aiosqlite parity test for async text execution and transactions; `aiosqlite` joins the dev extras.
- Add an initial Tokio-native asynchronous MySQL driver per ADR 0004 (`mysql_async`): `mysql://` URL routing in `create_async_engine`, a bounded QueuePool-style connection pool (timed checkout, reset-on-return rollback, dead-connection skipping, dispose), named `:bind` parameters, DML rowcounts, transactions, `has_table` via `information_schema.TABLES`, and redacted error mapping (duplicate-key → `IntegrityError`). Statements run the prepared binary protocol for typed results — integer, float/double, text, date, `datetime(6)`, binary/blob, and decimal hydrate identically to SQLAlchemy+asyncmy; unpreparable statements fall back to the text protocol with column-type decoding. rustls TLS is the default; local plaintext requires explicit `sslmode=disable`. Compiled Core statements (no MySQL dialect compiler yet), executemany, savepoints, streaming, `TIME` values, and broad type coverage are not supported.
- Add `asyncmy` and `aiosqlite` to the dev dependencies for live SQLAlchemy MySQL/async-SQLite comparisons.
- Add a bounded async PostgreSQL connection pool with QueuePool-style semantics: configurable `pool_size`/`max_overflow`/`pool_timeout`, idle-client reuse, timed checkout raising `TimeoutError`, rollback reset-on-return, dead-client skipping, and dispose draining idle handles while in-flight checkouts close cleanly.
- Add PostgreSQL compiled-statement execution: `AsyncConnection.execute` runs `Select`/`Insert`/`Update`/`Delete`/`Compiled` statements natively, typed bind metadata coerces processed datetime/date/boolean/numeric values, mapping overrides order by bind name, `has_table` probes `pg_catalog`, and `MetaData.create_all`/`drop_all`/`Table.create`/`drop` pick the PostgreSQL dialect from the bind. Verified live against SQLAlchemy+psycopg, which reports `-1` INSERT rowcounts where Catalyst returns the true count; executemany raises `ArgumentError`.
- Add PostgreSQL dialect compilation for Core select/insert/update/delete and CREATE/DROP TABLE via `compile(dialect="postgresql")`: `$N` placeholders, typed bind casts (`::INTEGER`/`::VARCHAR`/`::TIMESTAMP WITHOUT TIME ZONE`/`::DATE`), inferred casts for untyped binds, inline `true`/`false` literals, `||` string concatenation, `CAST(... AS NUMERIC/FLOAT)` true division, SQLAlchemy's empty-IN/NOT-IN forms, `LIMIT ALL OFFSET` pagination, SERIAL single-integer primary keys, PostgreSQL type names, and reserved-word quoting. Statement pairs, empty-IN forms, DDL variants, and identifier quoting are proven against SQLAlchemy's PostgreSQL dialect (pyformat binds normalized to `$N`); the plan cache is dialect-scoped. Execution over PostgreSQL remains text-only.
- Align SQLite string-operand `+` with SQLAlchemy's `||` concatenation (proving test added).
- Add an initial Tokio-native asynchronous PostgreSQL text driver: PostgreSQL URL routing in `create_async_engine`, safe named-bind scanning, buffered primitive SELECT results, DML rowcounts, basic transactions, redacted error mapping, and rustls certificate/hostname verification by default (explicit `sslmode=disable` only for local plaintext). No PostgreSQL pool, ORM, savepoints, streaming, or broad SQLAlchemy parity is claimed.
- Add SQLAlchemy-compatible SQLite Core type processing for declared Integer/String/Text/Boolean/Float/Date/DateTime and binary columns, including typed binds/results, formatted datetime storage, checked ISO result hydration, and result timezone offsets. SQLite timezone offsets are dropped on storage like SQLAlchemy; Numeric/Decimal remains unsupported.
- Add one-crossing SQLite executemany for compiled Core DML and text/positional batches, with aggregate rowcount and SQLAlchemy-like transaction behavior on batch failure; SELECT executemany raises ProgrammingError. Empty parameter sequences on compiled statements execute once with compiled values, including `DEFAULT VALUES` inserts. Async execution uses the same native batch path.
- Add a two-layer deterministic plan cache: Python-side LRU memoization of compiled Core statements keyed by the serialized statement, and Rust-side bounded per-connection prepared-statement caching (capacity 128) via rusqlite; measured ~4.5x faster repeated execution.

- Add native SQLite DDL compilation: SQLAlchemy-exact `CREATE TABLE`/`DROP TABLE` text in Rust (types, single/composite primary keys, NOT NULL, column-level UNIQUE, string `server_default` literals), `NativeConnection.has_table` probes matching SQLAlchemy's sqlite checkfirst pragmas, and Python `MetaData.create_all`/`drop_all` plus `Table.create`/`drop` for sync and async engine binds with checkfirst semantics and commit handling.
- Finish expression-compiler divergences: SQLAlchemy `is_precedent`/natural-self-precedent parenthesization for arithmetic and boolean groups, the SQLite `left / (right + 0.0)` true-division rewrite, `anon_N` labels for unlabeled non-column select items, empty `select()`, dropped empty `and_()`/`or_()` with SQLAlchemy's deprecation message (as `DeprecationWarning`), and `NOT` grouping for arithmetic/nested-negation shapes; `not_` now also reverses `not_in`/`not_like_escape`/`not_between`.
- Map SQLite prepare-time driver errors (`SqlInputError`) to `OperationalError` (constraint violations to `IntegrityError`), matching SQLAlchemy's sqlite DBAPI classification for errors such as "table already exists".
- Add a Rust-backed SQLite Core expression AST/compiler with SQLAlchemy-shaped table/column metadata, select/insert/update/delete construction, per-column scalar/expanding bind names, operator-aware negation, scalar `IS`, escaped `LIKE`, duplicate-column labels, empty `IN` handling, and a native expression-depth guard; document partial parity and unsupported AST features.
- Add a Tokio-backed SQLite async engine skeleton (`create_async_engine`, async connection execution/transactions, context managers, and disposal). Async results reuse the natively buffered `CursorResult`; no async streaming or full SQLAlchemy async parity is claimed.
- Store transaction/savepoint bookkeeping on physical pool slots, aligning serialized SQLite `:memory:` checkout interleaving and shared commit/rollback behavior with SQLAlchemy; retain independent file connections and add async checkout exhaustion coverage.

- Bootstrap the Rust workspace and Python package metadata for PyO3/maturin with the Python 3.10 stable ABI.
- Add a tested SQLAlchemy-style native exception hierarchy, Python API, and stubs.
- Add a foundation rusqlite-backed positional `sqlite_text` helper with bulk result conversion and parity tests.
- Record Rust-first architecture, driver/docs decisions, parity status, and local CI instructions.
- Remove the generated GitHub Actions workflow per project direction; CI is local only.
- Add a synchronous SQLite engine facade: Rust `NativeEngine`/`NativeResult` (buffered results, GIL-released execution) behind Python `create_engine`, `Engine`, `Connection`, and `CursorResult` with context managers, dispose lifecycle, use-after-close guards, and parity tests.
- Replace the engine's shared SQLite handle with a Rust bounded pool: distinct reusable file connections, a singleton connection for `:memory:`, and SQLAlchemy-style `TimeoutError` on immediate pool exhaustion; add pool unit and SQLAlchemy parity tests.
- Add Python `text()`/`TextClause` and Rust-native SQLite named binds (`:name`, `@name`, `$name`), escaped literal colons, positional execution compatibility, and result/error parity tests.
- Add Rust-native SQLite commit-as-you-go transactions and arbitrary nested savepoints, Python root/savepoint transaction shells and `Engine.begin()`, rollback-on-close, and SQLAlchemy parity tests.
- Add SQLAlchemy-style SQLite URL and engine option parsing, dialect error registry, configurable pool size/overflow and condition-variable checkout timeout, SQL echo logging, and parity tests.
- Select planned PostgreSQL (`tokio-postgres`) and MySQL (`mysql_async`) clients in ADRs 0003/0004 and add a Docker-backed plaintext protocol harness; no non-SQLite driver code or parity is implemented.
- Add opt-in Rust coverage through `cargo-llvm-cov` and Rust-only Criterion benchmarks for pool checkout, buffered SQLite queries, named binds, and transaction cycles; both are optional local CI gates.
