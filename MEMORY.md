- SQLite is selected through `rusqlite` bundled feature (ADR 0001). `sqlite_text(sql, parameters)` uses a process-local, in-memory connection, accepts scalar positional parameters, executes without holding GIL, and bulk-converts rows. `NativeEngine` owns a configurable Rust pool (`src/pool.rs`): file engines open up to `pool_size + max_overflow` connections, reserve capacity under a mutex before file opens outside it, wait with a Condvar up to `pool_timeout`, retain at most `pool_size` idle connections, and reset on return; `:memory:` engines use one shared connection. Exhaustion maps to `TimeoutError` with SQLAlchemy's MRO. URL/config options and the small Python dialect registry live in `catalyst.engine`. SQLite `timeout` configures rusqlite busy wait, separate from pool checkout timeout. `echo` logs once per statement. Public `text()`/`TextClause` supports named mappings via Rust SQLite parameter metadata, escaped `\\:` literal colons, repeated names, and ignored extra mapping keys. Missing named binds map to `StatementError`. Positional string execution remains available. SQLite transactions and savepoints are implemented natively with transaction state per physical pool slot; the `:memory:` singleton shares transaction/savepoint state across logical checkouts, while file slots remain independent. Python transaction shells provide context-manager ergonomics. Two-phase transactions, reset-agent behavior, transaction event hooks, and non-SQLite drivers remain unsupported. A SQLite async engine skeleton now uses `pyo3-async-runtimes` 0.29.0 (PyO3 0.29-compatible) plus pinned Tokio 1.45.1 with the multi-thread runtime. The bridge is initialized in extension module init; async checkout/dispose and execution/transaction control use Tokio `spawn_blocking`, with the synchronous driver methods continuing to release the GIL via `Python::detach`. The async shell reuses fully buffered `CursorResult`.
