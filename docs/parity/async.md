## Known gaps and documented differences

- **No async ORM**: `AsyncSession`, async lazy/eager loading, and async identity-map/UOW behavior are entirely unimplemented — the ORM is synchronous and SQLite-bound.
- **Buffered results only**: no streaming, server-side cursors, or `AsyncResult`; every async execute buffers the full result set.
- **SQLite async is a `spawn_blocking` wrapper** over the synchronous engine/pool — not a native async SQLite driver; `aiosqlite` parity is asserted only for the tested text/savepoint paths.
- **Cancellation is untested**: dropping a future mid-execution has no specified semantics; pool checkout timeouts raise `TimeoutError` like SQLAlchemy's QueuePool.
- **PostgreSQL/MySQL async pools** implement `pool_size`/`max_overflow`/`pool_timeout` with QueuePool-style exhaustion, idle reuse, reset-on-return rollback, dead-client skipping, and dispose draining — no `pool_pre_ping`, recycle, or per-connection options (see `docs/parity/dialects.md`).
- **Savepoint naming/guards**: `AsyncSavepointTransaction` uses `catalyst_sp_N` names and raises `InvalidRequestError` on guard errors where SQLAlchemy warns; `commit()`/`rollback()` before `start()` reject.
