# Core parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| SQLite `text()` with positional and named bound parameters | partial | `tests/test_text.py`, `tests/test_sqlite_text.py` | Public `text()` supports native SQLite `:name`, `@name`, and `$name` binds, escaped `\\:` literal colons, duplicate names, ignored extra keys, missing-key `StatementError`, and buffered keys/rowcount. Documented differences: `@name`/`$name` are a Catalyst extension (SQLAlchemy text() only parses `:name`); binds inside string literals are left literal by SQLite's own parameter parser where SQLAlchemy's regex would error or mangle; Catalyst's `StatementError` is a bare class without SQLAlchemy's `.orig`/`.params`/`.statement` attributes; list parameters with `text()` raise matching `ArgumentError` (executemany lists of dicts unsupported); `?NNN` numbered placeholders with a mapping raise `ProgrammingError` in both. `bindparams()` typing, executemany, and outparams are unsupported; broader dialect and transaction parity remain open. |
| Core `select` / `insert` / `update` / `delete` expressions | not started | — | Expression AST not implemented. |
| Transactions and savepoints (SQLite) | partial | `tests/test_transaction.py` | Native SQLite connection state implements commit-as-you-go autobegin, explicit root transactions, arbitrary nested savepoints, engine transaction context, rollback on close, and pool reset-on-return for checkouts dropped without `close()`. Verified against SQLAlchemy for tested commit/rollback, savepoint, DDL, result, and invalid double-begin cases. Documented differences: `RootTransaction.commit()`/`rollback()` after the transaction already ended raises matching `InvalidRequestError`; a savepoint handle used after its root ended raises clean `InvalidRequestError` where SQLAlchemy warns and no-ops; releasing an outer savepoint with an inner still active also raises `InvalidRequestError` where SQLAlchemy surfaces a driver error after a warning; context-manager exit on an already-ended transaction no-ops where SQLAlchemy warns. Rowcount uses a leading-keyword DML classification, so CTE-prefixed DML (`WITH ...`) reports -1. Two-phase transactions, transaction event hooks, isolation-level configuration, and non-SQLite dialects are unsupported. |
| SQLAlchemy-style exception names and supported DBAPI subclass hierarchy | partial | `tests/test_errors.py` | Supported exception classes are compared with SQLAlchemy; constructors, attributes, and the full exception set are not covered. `CatalystError` is an alias of `SQLAlchemyError`. |
| Synchronous `create_engine` / `Engine.connect` / `Connection.execute` for SQLite text statements | partial | `tests/test_sqlite_text.py`, `tests/test_transaction.py` | Catalyst's engine, pooled file connections, singleton `:memory:` connection semantics, buffered `CursorResult`, context managers, dispose lifecycle, exhaustion error class, and SQLite transaction lifecycle are compared with SQLAlchemy. Pool exhaustion raises SQLAlchemy-style `TimeoutError` immediately rather than waiting; pool sizing/timeouts, URL options, and dialect registry remain unsupported. |
