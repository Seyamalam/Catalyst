# Dialect parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |

| SQLite positional text execution | partial | `tests/test_sqlite_text.py` | A foundation helper uses rusqlite; no dialect compiler or engine/pool API exists. |
| PostgreSQL async text execution | partial | `tests/test_postgres.py::test_postgres_named_text_select_dml_and_transactions` | Tokio-native connection; named `:bind` parameters, buffered primitive SELECT results, DML rowcount, and basic transactions. `begin_nested` savepoints (`SAVEPOINT`/`RELEASE SAVEPOINT`/`ROLLBACK TO SAVEPOINT`) are supported on the async connection — see the async matrix. No ORM, executemany, streaming, or broad type support. Real test requires `CATALYST_POSTGRES_URL`; text exceptions redact driver messages. TLS verification is default; local plaintext requires explicit `sslmode=disable`. |
| PostgreSQL async connection pool | partial | `tests/test_postgres_pool.py` | Bounded async pool with QueuePool-style semantics: `pool_size`/`max_overflow`/`pool_timeout` options (`max_overflow=-1` unlimited), idle-client reuse (verified via `pg_backend_pid()`), timed checkout raising `TimeoutError` with SQLAlchemy's QueuePool message shape, reset-on-return rollback of uncommitted checkouts, dead-client skipping, and dispose draining idle handles while in-flight checkouts close cleanly. Compared with SQLAlchemy `AsyncAdaptedQueuePool` for exhaustion and rollback-on-return. No `pool_pre_ping`, recycle, or per-connection options. |
| PostgreSQL compiled Core execution | partial | `tests/test_postgres_core.py` | `AsyncConnection.execute` accepts `Select`/`Insert`/`Update`/`Delete` (compiled to `postgresql` on the fly) and `Compiled` statements; `MetaData.create_all`/`drop_all` and `Table.create`/`drop` select the PostgreSQL DDL dialect from the bind, and `connection.has_table` runs a search-path `pg_catalog` probe. Typed bind metadata reinterprets compile-processed values natively (datetime/date strings, booleans, integer/float/binary, `Decimal` via the binary NUMERIC codec) and user mapping overrides are ordered by bind name. Verified live against SQLAlchemy+psycopg for DDL catalog shape, typed DML/SELECT round trips, where/order/limit/offset/IN/LIKE/BETWEEN/empty-IN clauses, NULL inserts, `IntegrityError` on duplicate keys, and `Numeric` round trips including `NaN`/`Infinity`/`-Infinity` and numeric-overflow `DataError`. Parameter-mapping executemany batches run once per group on the checked-out connection inside one transaction with an aggregated rowcount. Differences: SQLAlchemy+psycopg reports `-1` INSERT rowcounts (its `insertmanyvalues` path) where Catalyst returns the true count. No joins, RETURNING, or schemas. |
| PostgreSQL dialect compilation (Core and DDL) | partial | `tests/test_postgres_dialect.py` | Rust renders PostgreSQL SQL for select/insert/update/delete and CREATE/DROP TABLE via `compile(dialect="postgresql")`: `$N` positional placeholders (parity tests normalize SQLAlchemy's `%(name)s` pyformat binds by first appearance), typed bind casts (`::INTEGER`, `::VARCHAR`, `::TIMESTAMP WITHOUT TIME ZONE`, `::DATE`) and inferred casts for untyped binds, inline `true`/`false` boolean literals, `||` string concatenation, `CAST(... AS NUMERIC/FLOAT)` true division, SQLAlchemy's empty-IN/NOT-IN forms, `LIMIT ALL OFFSET` pagination, SERIAL single-integer primary keys, PostgreSQL type names, and reserved-word/identifier quoting. Compilation is dialect-scoped in the plan cache; unknown dialects raise `ArgumentError`. No joins, aliases, CTEs, RETURNING, schemas, executemany, or broad type support. |
| MySQL async text execution | partial | `tests/test_mysql.py`; `tests/test_mysql_executemany.py` | Tokio-native driver per [ADR 0004](../decisions/0004-mysql-driver.md) (`mysql_async`, rustls TLS by default; local plaintext requires explicit `sslmode=disable`). Named `:bind` parameters, DML rowcounts, transactions (autobegin, commit, rollback, explicit `begin`), `has_table` via `information_schema.TABLES`, and executemany batches of `:bind` mappings (see the executemany row). An empty parameter sequence on `text()` still binds once — a required named bind raises `StatementError` ("A value is required for bind parameter ...") rather than leaking the `:name` to the server. Statements run the prepared binary protocol (`COM_STMT_EXECUTE`) for typed results — integer, float/double, text, date, `datetime(6)`, binary/blob, and decimal hydrate natively, verified identical to SQLAlchemy+asyncmy; unpreparable statements (e.g. `SHOW`) fall back to the text protocol with column-type decoding. Errors map onto the SQLAlchemy hierarchy (duplicate-key 1062 → `IntegrityError`, redacted connect failures). Compiled Core statements execute via the MySQL dialect (see the next rows); no streaming, `TIME` values, or broad type coverage. |
| MySQL compiled Core execution | partial | `tests/test_mysql_core.py`; `tests/test_mysql_executemany.py` | `AsyncConnection.execute` accepts `Select`/`Insert`/`Update`/`Delete` (compiled to `mysql` on the fly) and `Compiled` statements, including executemany parameter-mapping batches (compiled `INSERT ... VALUES (?)` batches collapse into one atomic multi-row statement like asyncmy — see the executemany row); `MetaData.create_all`/`drop_all` and `Table.create`/`drop` select the MySQL DDL dialect from the bind. Typed bind metadata reinterprets compile-processed values for the binary protocol (datetime/date strings, booleans, integer/float/binary, `Decimal` sent as text bytes the server coerces) and user mapping overrides are ordered by bind name. Verified live against SQLAlchemy+asyncmy for DDL catalog shape (`information_schema.columns` identical, `auto_increment` extra), typed DML/SELECT round trips, where/order/limit/offset/IN/LIKE/BETWEEN/empty-IN/IS clauses, NULL inserts, reserved-identifier quoting, and `IntegrityError` on duplicate keys. Differences: `DateTime` maps to `DATETIME` with fsp 0 (fractional seconds truncate) matching SQLAlchemy's rendering. No joins or schemas. |
| MySQL executemany | partial | `tests/test_mysql_executemany.py`; `tests/test_mysql.py::test_mysql_select_executemany_runs_per_group_like_sqlalchemy` | `AsyncConnection.execute` accepts a non-empty list of parameter mappings for compiled `Insert`/`Update`/`Delete`/`Compiled` statements and `text()` `:bind` statements (positional rows on those statements are rejected Python-side with `ArgumentError` like SQLAlchemy), plus positional-row batches for raw `?` SQL. The whole batch crosses the FFI boundary once: Rust orders each mapping by the compiled `bind_names` (or the scanned `:name` sequence for `text()`), coerces values through the typed bind metadata, and matches verified SQLAlchemy+asyncmy semantics — `INSERT`/`REPLACE ... VALUES (?)` batches collapse into a single multi-row statement inside one transaction (atomic across the batch: a mid-batch duplicate key raises `IntegrityError` and leaves zero rows visible pre-rollback), while every other statement shape executes once per parameter group with result sets discarded and the rowcount summed. SELECT batches are not rejected — `text()` and compiled selects run per group and report `[]` rows with the aggregated rowcount (asyncmy parity; PyMySQL diverges by raising `ProgrammingError` — "executemany() can only execute DML statements." — which Catalyst does not reproduce). Error shapes match SQLAlchemy: missing keys raise `StatementError` naming the bind with `, in parameter group N` appended only for group N ≥ 1, an empty `text()` batch still binds once and raises the missing-bind `StatementError`, and bind-conversion failures arrive as `StatementError` with `.orig`/`.statement`/`.params`. Residual gap: SA+asyncmy forwards bad bind values to the server and surfaces `DataError` (errno 1366) where Catalyst rejects them client-side as `StatementError` wrapping `TypeError` — same `StatementError` family, different leaf class. Insert batches fix their shape from the first row plus statement `.values()` like SQLAlchemy. Batch result rows/RETURNING are not implemented (empty result, aggregated rowcount only). |
| MySQL dialect compilation (Core and DDL) | partial | `tests/test_mysql_core.py::test_mysql_compiled_expressions_match_sqlalchemy`; `tests/test_mysql.py` | Rust renders MySQL SQL for select/insert/update/delete and CREATE/DROP TABLE via `compile(dialect="mysql")`: `?` positional placeholders for `mysql_async` (parity tests normalize SQLAlchemy's `%s` binds), inline `true`/`false` boolean literals and `true = 1`/`false = 1` boolean words, `concat(...)` string concatenation, plain `/` division, `IN (NULL) AND (1 != 1)`/`NOT IN (NULL) OR (1 = 1)` empty sets, `LIMIT offset, count` pagination (offset-only renders the `18446744073709551615` count), backtick identifier quoting with the MySQL 8.x reserved-word table, `INTEGER ... AUTO_INCREMENT` single-integer primary keys with a separate `PRIMARY KEY` clause, empty inserts as explicit NULL binds, and MySQL type names (`VARCHAR(n)`/`TEXT`/`BOOL`/`FLOAT`/`DATETIME`/`DATE`/`BLOB`). Compilation is dialect-scoped in the plan cache. No joins, aliases, CTEs, RETURNING, schemas, executemany, or broad type support. |
| MySQL async connection pool | partial | `tests/test_mysql.py::test_mysql_pool_reuses_returned_connections`; `tests/test_mysql.py::test_mysql_pool_exhaustion_times_out_like_sqlalchemy`; `tests/test_mysql.py::test_mysql_pool_dispose_rejects_new_checkouts`; `tests/test_mysql.py::test_mysql_pool_concurrent_checkout_stress` | Same bounded QueuePool-style semantics as the PostgreSQL pool: `pool_size`/`max_overflow`/`pool_timeout`, idle reuse (verified via `CONNECTION_ID()`), timed checkout `TimeoutError`, reset-on-return rollback of uncommitted checkouts, dead-connection skipping, and dispose behavior compared with SQLAlchemy+asyncmy. |
