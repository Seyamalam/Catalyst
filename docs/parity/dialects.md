# Dialect parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| SQLite positional text execution | partial | `tests/test_sqlite_text.py` | A foundation helper uses rusqlite; no dialect compiler or engine/pool API exists. |
| PostgreSQL async text execution | partial | `tests/test_postgres.py::test_postgres_named_text_select_dml_and_transactions` | Tokio-native single connection; named `:bind` parameters, buffered primitive SELECT results, DML rowcount, and basic transactions. No pool; no ORM, savepoints, executemany, streaming, or broad type support. Real test requires `CATALYST_POSTGRES_URL`; text exceptions redact driver messages. TLS verification is default; local plaintext requires explicit `sslmode=disable`. |
| PostgreSQL compiled Core execution | partial | `tests/test_postgres_core.py` | `AsyncConnection.execute` accepts `Select`/`Insert`/`Update`/`Delete` (compiled to `postgresql` on the fly) and `Compiled` statements; `MetaData.create_all`/`drop_all` and `Table.create`/`drop` select the PostgreSQL DDL dialect from the bind, and `connection.has_table` runs a search-path `pg_catalog` probe. Typed bind metadata reinterprets compile-processed values natively (datetime/date strings, booleans, integer/float/binary) and user mapping overrides are ordered by bind name. Verified live against SQLAlchemy+psycopg for DDL catalog shape, typed DML/SELECT round trips, where/order/limit/offset/IN/LIKE/BETWEEN/empty-IN clauses, NULL inserts, and `IntegrityError` on duplicate keys. Differences: SQLAlchemy+psycopg reports `-1` INSERT rowcounts (its `insertmanyvalues` path) where Catalyst returns the true count; PostgreSQL executemany raises `ArgumentError`. No joins, RETURNING, schemas, pool, or savepoints. |
| PostgreSQL dialect compilation (Core and DDL) | partial | `tests/test_postgres_dialect.py` | Rust renders PostgreSQL SQL for select/insert/update/delete and CREATE/DROP TABLE via `compile(dialect="postgresql")`: `$N` positional placeholders (parity tests normalize SQLAlchemy's `%(name)s` pyformat binds by first appearance), typed bind casts (`::INTEGER`, `::VARCHAR`, `::TIMESTAMP WITHOUT TIME ZONE`, `::DATE`) and inferred casts for untyped binds, inline `true`/`false` boolean literals, `||` string concatenation, `CAST(... AS NUMERIC/FLOAT)` true division, SQLAlchemy's empty-IN/NOT-IN forms, `LIMIT ALL OFFSET` pagination, SERIAL single-integer primary keys, PostgreSQL type names, and reserved-word/identifier quoting. Compilation is dialect-scoped in the plan cache; unknown dialects raise `ArgumentError`. No joins, aliases, CTEs, RETURNING, schemas, executemany, or broad type support. |
| MySQL dialect and execution | not started | — | Driver selected in [ADR 0004](../decisions/0004-mysql-driver.md); no driver code or SQLAlchemy parity test exists. |
| Docker integration harness: plaintext service protocol probes | partial | `tests/test_integration_infra.py::test_postgres_plaintext_startup_response`; `tests/test_integration_infra.py::test_mysql_plaintext_protocol_greeting` | Harness-infrastructure coverage only: checks TCP and initial protocol framing with TLS disabled. Real PostgreSQL SQL execution is proven separately by `tests/test_postgres.py`; no PostgreSQL TLS-enabled server or SQLAlchemy cross-driver parity test is included. |
