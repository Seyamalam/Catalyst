# Dialect parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| SQLite positional text execution | partial | `tests/test_sqlite_text.py` | A foundation helper uses rusqlite; no dialect compiler or engine/pool API exists. |
| PostgreSQL async text execution | partial | `tests/test_postgres.py::test_postgres_named_text_select_dml_and_transactions` | Tokio-native connection; named `:bind` parameters, buffered primitive SELECT results, DML rowcount, and basic transactions. `begin_nested` savepoints (`SAVEPOINT`/`RELEASE SAVEPOINT`/`ROLLBACK TO SAVEPOINT`) are supported on the async connection — see the async matrix. No ORM, executemany, streaming, or broad type support. Real test requires `CATALYST_POSTGRES_URL`; text exceptions redact driver messages. TLS verification is default; local plaintext requires explicit `sslmode=disable`. |
| PostgreSQL async connection pool | partial | `tests/test_postgres_pool.py` | Bounded async pool with QueuePool-style semantics: `pool_size`/`max_overflow`/`pool_timeout` options (`max_overflow=-1` unlimited), idle-client reuse (verified via `pg_backend_pid()`), timed checkout raising `TimeoutError` with SQLAlchemy's QueuePool message shape, reset-on-return rollback of uncommitted checkouts, dead-client skipping, and dispose draining idle handles while in-flight checkouts close cleanly. Compared with SQLAlchemy `AsyncAdaptedQueuePool` for exhaustion and rollback-on-return. No `pool_pre_ping`, recycle, or per-connection options. |
| PostgreSQL compiled Core execution | partial | `tests/test_postgres_core.py` | `AsyncConnection.execute` accepts `Select`/`Insert`/`Update`/`Delete` (compiled to `postgresql` on the fly) and `Compiled` statements; `MetaData.create_all`/`drop_all` and `Table.create`/`drop` select the PostgreSQL DDL dialect from the bind, and `connection.has_table` runs a search-path `pg_catalog` probe. Typed bind metadata reinterprets compile-processed values natively (datetime/date strings, booleans, integer/float/binary) and user mapping overrides are ordered by bind name. Verified live against SQLAlchemy+psycopg for DDL catalog shape, typed DML/SELECT round trips, where/order/limit/offset/IN/LIKE/BETWEEN/empty-IN clauses, NULL inserts, and `IntegrityError` on duplicate keys. Differences: SQLAlchemy+psycopg reports `-1` INSERT rowcounts (its `insertmanyvalues` path) where Catalyst returns the true count; PostgreSQL executemany raises `ArgumentError`. No joins, RETURNING, or schemas. |
| PostgreSQL dialect compilation (Core and DDL) | partial | `tests/test_postgres_dialect.py` | Rust renders PostgreSQL SQL for select/insert/update/delete and CREATE/DROP TABLE via `compile(dialect="postgresql")`: `$N` positional placeholders (parity tests normalize SQLAlchemy's `%(name)s` pyformat binds by first appearance), typed bind casts (`::INTEGER`, `::VARCHAR`, `::TIMESTAMP WITHOUT TIME ZONE`, `::DATE`) and inferred casts for untyped binds, inline `true`/`false` boolean literals, `||` string concatenation, `CAST(... AS NUMERIC/FLOAT)` true division, SQLAlchemy's empty-IN/NOT-IN forms, `LIMIT ALL OFFSET` pagination, SERIAL single-integer primary keys, PostgreSQL type names, and reserved-word/identifier quoting. Compilation is dialect-scoped in the plan cache; unknown dialects raise `ArgumentError`. No joins, aliases, CTEs, RETURNING, schemas, executemany, or broad type support. |
| MySQL async text execution | partial | `tests/test_mysql.py` | Tokio-native driver per [ADR 0004](../decisions/0004-mysql-driver.md) (`mysql_async`, rustls TLS by default; local plaintext requires explicit `sslmode=disable`). Named `:bind` parameters, DML rowcounts, transactions (autobegin, commit, rollback, explicit `begin`), and `has_table` via `information_schema.TABLES`. Statements run the prepared binary protocol (`COM_STMT_EXECUTE`) for typed results — integer, float/double, text, date, `datetime(6)`, binary/blob, and decimal hydrate natively, verified identical to SQLAlchemy+asyncmy; unpreparable statements (e.g. `SHOW`) fall back to the text protocol with column-type decoding. Errors map onto the SQLAlchemy hierarchy (duplicate-key 1062 → `IntegrityError`, redacted connect failures). No compiled Core statements (MySQL dialect compiler is not implemented — `Select`/`Insert`/`Update`/`Delete` raise `ArgumentError`), no executemany, streaming, `TIME` values, or broad type coverage. |
| MySQL async connection pool | partial | `tests/test_mysql.py::test_mysql_pool_reuses_returned_connections`; `tests/test_mysql.py::test_mysql_pool_exhaustion_times_out_like_sqlalchemy`; `tests/test_mysql.py::test_mysql_pool_dispose_rejects_new_checkouts`; `tests/test_mysql.py::test_mysql_pool_concurrent_checkout_stress` | Same bounded QueuePool-style semantics as the PostgreSQL pool: `pool_size`/`max_overflow`/`pool_timeout`, idle reuse (verified via `CONNECTION_ID()`), timed checkout `TimeoutError`, reset-on-return rollback of uncommitted checkouts, dead-connection skipping, and dispose behavior compared with SQLAlchemy+asyncmy. |
| Docker integration harness: plaintext service protocol probes | partial | `tests/test_integration_infra.py::test_postgres_plaintext_startup_response`; `tests/test_integration_infra.py::test_mysql_plaintext_protocol_greeting` | Harness-infrastructure coverage only: checks TCP and initial protocol framing with TLS disabled. Real PostgreSQL SQL execution is proven separately by `tests/test_postgres.py`; no PostgreSQL TLS-enabled server or SQLAlchemy cross-driver parity test is included. |
