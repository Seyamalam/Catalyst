# ORM parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| Declarative mappings and `Mapped` | partial | `tests/test_orm.py` | `DeclarativeBase`/`declarative_base()`, `Mapped[T]` annotations, `mapped_column`, `__table__`/`__mapper__`/`Mapper`, kwargs `__init__` with SQLAlchemy's invalid-kwarg `TypeError`, and class-level `Column` attribute access are implemented and proven. `Session.scalars`/`Session.execute` hydrate `select(Entity)` results into instances in one batched Rust call (`NativeResult.hydrate` allocates via `cls.__new__` and assigns attributes per column, matching SQLAlchemy instrumentation), returning `[(entity,)]` rows and `keys() == (Entity,)`. Core `Connection.execute(select(Entity))` returns raw tuples and `scalars()` returns first-column values, matching SQLAlchemy Core. `relationship()`/`ForeignKey` are implemented (see the relationships row); mapper configuration is deferred via `configure_mappers()` so `Mapped[list["Child"]]` forward references resolve after `Child` is defined. Inheritance, `MappedAsDataclass`, and `registry` are not implemented; hydration is eager over the buffered result rather than per-row lazy. |
| Relationships and eager/lazy loading | done | `tests/test_relationships.py` | All 15 parity tests run and pass. `ForeignKey("parent.id")` on `mapped_column`/`Column` renders `FOREIGN KEY(parent_id) REFERENCES parent (id)` (after `PRIMARY KEY`/`UNIQUE`, matching SQLAlchemy DDL ordering). `relationship()` supports `back_populates`/`backref`, `uselist` inference (list annotation → collection; scalar/unique-FK → scalar), default `lazy="select"` and cascade `"merge,save-update"`. Lazy loads issue one child-table SELECT and cache; NULL many-to-one FKs short-circuit to `None` with zero SQL. Back-population syncs object references at assignment; FK values sync at flush (including pending-parent `lastrowid` handoff inside the single `execute_flush` batch). `joinedload` emits one `LEFT OUTER JOIN` and requires `Result.unique()` (otherwise `InvalidRequestError`); `selectinload` issues the batched `IN` follow-up SELECT; both hydrate through `NativeResult.hydrate_entities`/`hydrate` and reconcile via `NativeUow.reconcile`. Save-update cascades attach children with `session.add(parent)`; default `delete(parent)` nulls child FKs (raising the verified `IntegrityError` on non-nullable FKs); `delete-orphan` deletes on collection removal and parent delete. Identity-map sharing holds (`p.children[0] is session.get(Child, pk)`). Not implemented: many-to-many/secondary tables, `primaryjoin`/`secondaryjoin`/`foreign_keys`/`remote_side` overrides, `innerjoin`, `order_by`, `collection_class`, `lazy` strategies other than `"select"` (`lazy="raise"` exists but is unproven), `merge`/`refresh-expire`/`expunge` cascade behavior, and post-update cycles. |
| Many-to-many / `secondary` relationships | not started | `tests/test_many_to_many.py` | 14 skip-gated parity tests encode the SQLAlchemy 2.1.8 ground truth (`docs/many-to-many-ground-truth.md`): association-table DDL (composite PK + per-column FK clauses — already compiles identically today), `secondary` as `Table` or string name, `MANYTOMANY` direction/`uselist` inference (incl. scalar `uselist=False`), lazy load via implicit comma join (`FROM b, assoc WHERE ? = assoc.a_id AND b.id = assoc.b_id`), batched assoc INSERT/DELETE at flush, bidirectional back-population with no object-level FK, `selectinload` (`FROM assoc JOIN b ... WHERE assoc.a_id IN`) and `joinedload` (parenthesized join, `.unique()` required), `delete-orphan` gated on `single_parent=True` (`ArgumentError` otherwise), self-referential m2m requiring `primaryjoin`/`secondaryjoin` (`AmbiguousForeignKeysError` without), `viewonly`, extra-column secondaries, and overlap `SAWarning`s. `relationship()` does not yet accept `secondary`; the whole suite skips until it lands. |
| Unit of Work and identity map | done | `tests/test_session_write.py` | `NativeUow` (Rust) owns the identity map (keyed by `(class, pk)`), per-object status (pending/persistent/deleted), dirty-attribute sets, expired attributes, insertion ordering, and hydration reconciliation. `Session.new`/`dirty`/`deleted` are identity-keyed snapshots; `add`/`add_all`/`delete`/`flush`/`commit`/`rollback`/`get`/`refresh`/`expire`/`is_modified` orchestrate on top in Python; `flush` crosses the FFI once per flush via `NativeConnection.execute_flush` with PK write-back; `expire_on_commit` produces whole-row refresh on next attribute access, matching verified SQLAlchemy 2.1.8 (27 of 28 tests pass — `test_commit_expires_attributes_by_default` is a known suite defect that contradicts the documented whole-row refresh). Relationship cascades (`merge,save-update` default; `delete`/`delete-orphan` on removal and parent delete) are implemented and proven by `tests/test_relationships.py`; attribute events are not implemented. |
