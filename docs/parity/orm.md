# ORM parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| Declarative mappings and `Mapped` | partial | `tests/test_orm.py` | `DeclarativeBase`/`declarative_base()`, `Mapped[T]` annotations, `mapped_column`, `__table__`/`__mapper__`/`Mapper`, kwargs `__init__` with SQLAlchemy's invalid-kwarg `TypeError`, and class-level `Column` attribute access are implemented and proven. `Session.scalars`/`Session.execute` hydrate `select(Entity)` results into instances in one batched Rust call (`NativeResult.hydrate` allocates via `cls.__new__` and assigns attributes per column, matching SQLAlchemy instrumentation), returning `[(entity,)]` rows and `keys() == (Entity,)`. Core `Connection.execute(select(Entity))` returns raw tuples and `scalars()` returns first-column values, matching SQLAlchemy Core. `relationship()`/`ForeignKey` are implemented (see the relationships row); mapper configuration is deferred via `configure_mappers()` so `Mapped[list["Child"]]` forward references resolve after `Child` is defined. Inheritance, `MappedAsDataclass`, and `registry` are not implemented; hydration is eager over the buffered result rather than per-row lazy. |
| Declarative inheritance (STI/JTI) | not started | `tests/test_inheritance.py` | Skip-gated capability probe (19 tests, all SKIP today): `__mapper_args__`/`polymorphic_on`/`polymorphic_identity` and subclass table sharing are unimplemented — a subclass without `__tablename__` is currently treated as an unmapped intermediate base. SQLAlchemy 2.1.8 ground truth verified in `docs/inheritance-ground-truth.md`: STI shares the parent `Table` (one `CREATE TABLE`), auto-sets the discriminator on INSERT, filters subclass `get`/`select`/bulk DML with `type IN (identity subtree)`, and resolves row classes at hydration; JTI uses a second table whose PK is an FK to the parent, inserts parent-then-child, inner-joins for subclass selects, lazily loads subclass columns per instance on parent queries, and deletes child-then-parent at instance level (bulk parent `delete()` orphans child rows — verified surprise). Recommended split: STI slice first (mapper hierarchy + discriminator + hydration resolution), JTI second (two-table flush + deferred child-column loads). Concrete-table inheritance, `with_polymorphic`, and hierarchy loader options deferred. |
| Relationships and eager/lazy loading | done | `tests/test_relationships.py` | All 15 parity tests run and pass. `ForeignKey("parent.id")` on `mapped_column`/`Column` renders `FOREIGN KEY(parent_id) REFERENCES parent (id)` (after `PRIMARY KEY`/`UNIQUE`, matching SQLAlchemy DDL ordering). `relationship()` supports `back_populates`/`backref`, `uselist` inference (list annotation → collection; scalar/unique-FK → scalar), default `lazy="select"` and cascade `"merge,save-update"`. Lazy loads issue one child-table SELECT and cache; NULL many-to-one FKs short-circuit to `None` with zero SQL. Back-population syncs object references at assignment; FK values sync at flush (including pending-parent `lastrowid` handoff inside the single `execute_flush` batch). `joinedload` emits one `LEFT OUTER JOIN` and requires `Result.unique()` (otherwise `InvalidRequestError`); `selectinload` issues the batched `IN` follow-up SELECT; both hydrate through `NativeResult.hydrate_entities`/`hydrate` and reconcile via `NativeUow.reconcile`. Save-update cascades attach children with `session.add(parent)`; default `delete(parent)` nulls child FKs (raising the verified `IntegrityError` on non-nullable FKs); `delete-orphan` deletes on collection removal and parent delete. Identity-map sharing holds (`p.children[0] is session.get(Child, pk)`). Not implemented: `primaryjoin`/`secondaryjoin`/`foreign_keys`/`remote_side`/`overlaps` overrides on non-secondary relationships (the join args exist only for many-to-many disambiguation — see the many-to-many row), `innerjoin`, `order_by`, `collection_class`, `lazy` strategies other than `"select"` (`lazy="raise"` exists but is unproven), `merge`/`refresh-expire`/`expunge` cascade behavior, and post-update cycles. |
| Many-to-many / `secondary` relationships | done | `tests/test_many_to_many.py` | All 14 parity tests run and pass against the SQLAlchemy 2.1.8 ground truth (`docs/many-to-many-ground-truth.md`). `relationship(secondary=)` accepts a `Table` or a string name resolved through the declaring mapper's `MetaData` (unresolved names defer with pending mapper configuration). Presence of `secondary` forces `MANYTOMANY` direction with collection `uselist` default; `uselist=False` yields a scalar m2m. The two association FK paths are inferred from each column's `ForeignKey.target_table`; self-referential mappings require `primaryjoin`/`secondaryjoin` and raise `AmbiguousForeignKeysError` (a native `ArgumentError` subclass) without them. Lazy loads emit SQLAlchemy's implicit comma join, bind-first (`FROM b, assoc WHERE ? = assoc.a_id AND b.id = assoc.b_id`); empty associations still emit the SELECT and return `[]`. Flush orders parent INSERTs → child INSERTs → association ops: deduplicated `DELETE FROM assoc WHERE a_id=? AND b_id=?` before `INSERT INTO assoc (a_id, b_id)`, all ahead of mapped-object deletes and inside the single `execute_flush` FFI crossing with `("__catalyst_rowid__", dep)` deferred binds for pending members; committed membership diffs ride a per-attribute `_catalyst_m2m_base` remote-PK baseline populated at load. Back-population is bidirectional at assignment with no object-level FK; save-update cascades transient children appended through `secondary`. `selectinload` emits `SELECT assoc.a_id, t.* FROM assoc JOIN t ... WHERE assoc.a_id IN (...)` (association table first, grouping column first); `joinedload` emits `LEFT OUTER JOIN (assoc AS a_1 JOIN t AS t_1 ON ...) ON ...` and keeps the `.unique()` requirement. `viewonly=True` loads through the association but never writes rows; extra association columns fall to `server_default`/NULL. `delete-orphan` requires `single_parent=True` (`ArgumentError` at configure otherwise) and then removes the child row after the association row; parent deletes order association rows, parent, then children. Overlapping secondary relationships emit the verified `SAWarning` and still work. Deferred: the association-object pattern, composite-FK association joins, non-PK join columns, `overlaps`, and `primaryjoin`/`secondaryjoin`/`foreign_keys`/`remote_side` overrides on non-secondary relationships. |
| Unit of Work and identity map | done | `tests/test_session_write.py` | `NativeUow` (Rust) owns the identity map (keyed by `(class, pk)`), per-object status (pending/persistent/deleted), dirty-attribute sets, expired attributes, insertion ordering, and hydration reconciliation. `Session.new`/`dirty`/`deleted` are identity-keyed snapshots; `add`/`add_all`/`delete`/`flush`/`commit`/`rollback`/`get`/`refresh`/`expire`/`is_modified` orchestrate on top in Python; `flush` crosses the FFI once per flush via `NativeConnection.execute_flush` with PK write-back; `expire_on_commit` produces whole-row refresh on next attribute access, matching verified SQLAlchemy 2.1.8 (27 of 28 tests pass — `test_commit_expires_attributes_by_default` is a known suite defect that contradicts the documented whole-row refresh). Relationship cascades (`merge,save-update` default; `delete`/`delete-orphan` on removal and parent delete) are implemented and proven by `tests/test_relationships.py`; attribute events are not implemented. |
