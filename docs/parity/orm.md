# ORM parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| Declarative mappings and `Mapped` | partial | `tests/test_orm.py` | `DeclarativeBase`/`declarative_base()`, `Mapped[T]` annotations, `mapped_column`, `__table__`/`__mapper__`/`Mapper`, kwargs `__init__` with SQLAlchemy's invalid-kwarg `TypeError`, and class-level `Column` attribute access are implemented and proven. `Session.scalars`/`Session.execute` hydrate `select(Entity)` results into instances in one batched Rust call (`NativeResult.hydrate` allocates via `cls.__new__` and assigns attributes per column, matching SQLAlchemy instrumentation), returning `[(entity,)]` rows and `keys() == (Entity,)`. Core `Connection.execute(select(Entity))` returns raw tuples and `scalars()` returns first-column values, matching SQLAlchemy Core. Relationships, inheritance, `MappedAsDataclass`, `registry`, and `relationship()` are not implemented; hydration is eager over the buffered result rather than per-row lazy. |
| Relationships and eager/lazy loading | not started | `tests/test_relationships.py` (skip-gated) | No `relationship()`/`ForeignKey`/loader-option API yet; the 15-test parity suite is written and skips until they land. SQLAlchemy 2.1.8 ground truth (DDL `FOREIGN KEY ... REFERENCES`, `uselist`/`lazy`/cascade inference, lazy SELECT shapes, `joinedload`/`selectinload` SQL + `.unique()` requirement, save-update/delete-orphan cascades, assignment-vs-flush FK sync, identity-map sharing) is recorded in `docs/relationship-loading-ground-truth.md`. |
| Unit of Work and identity map | done | `tests/test_session_write.py` | `NativeUow` (Rust) owns the identity map (keyed by `(class, pk)`), per-object status (pending/persistent/deleted), dirty-attribute sets, expired attributes, insertion ordering, and hydration reconciliation. `Session.new`/`dirty`/`deleted` are identity-keyed snapshots; `add`/`add_all`/`delete`/`flush`/`commit`/`rollback`/`get`/`refresh`/`expire`/`is_modified` orchestrate on top in Python; `flush` crosses the FFI once per flush via `NativeConnection.execute_flush` with PK write-back; `expire_on_commit` produces whole-row refresh on next attribute access, matching verified SQLAlchemy 2.1.8 (27 of 28 tests pass — `test_commit_expires_attributes_by_default` is a known suite defect that contradicts the documented whole-row refresh). Relationship cascades and attribute events are not implemented. |
