# Session parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| `Session` query and persistence behavior | partial | `tests/test_orm.py` | `Session(bind)` wraps an `Engine`/`Connection` and exposes `execute`, `scalars`, `close`, and context-manager use. `scalars(select(Entity))` returns hydrated mapped instances matching SQLAlchemy's `Session.scalars` attribute values; `execute` returns `(entity,)` rows with `keys() == (Entity,)`; `one`/`one_or_none`/`first` raise or return like SQLAlchemy with `NoResultFound`/`MultipleResultsFound`. ORM `execute`/`scalars` results come through the Rust identity map, so repeated reads of the same row yield the identical Python object (`is`), matching SQLAlchemy. |
| `Session` write path and unit of work | partial | `tests/test_session_write.py` | `add`/`add_all`/`delete`/`flush`/`commit`/`rollback`/`get`/`refresh`, `new`/`dirty`/`deleted` identity-keyed sets, `is_modified`, `autoflush` (on `execute`/`scalars`/`get`), `expire_on_commit`, `expire`/`expire_all`, `close()`, `begin`/`in_transaction`, `UnmappedInstanceError`, and `PendingRollbackError` are implemented with SQLAlchemy 2.1.8 semantics: the PK stays `None` until flush (`lastrowid` write-back after the insert), pending inserts batch in add order, dirty tracking is set-on-write (reverting the value does not clear dirty), `flush` emits only dirty columns, commit with `expire_on_commit` expires every attribute so the next access re-SELECTs the whole row, `delete` on a pending object raises `InvalidRequestError`, rollback detaches newly flushed objects while keeping their Python-side values and expires dirty persistent state, a failed flush blocks subsequent operations with `PendingRollbackError` until `rollback()`, and the identity map guarantees `is`-identity across `get`/`scalars`. 27 of 28 tests pass; `test_commit_expires_attributes_by_default` is a known suite defect — its `obj.id` access after commit performs a whole-row refresh per `docs/session-write-ground-truth.md` (and verified SA 2.1.8), so the externally updated value the test expects is unreachable even for pure SQLAlchemy. `Session.begin_nested` nested-transaction semantics, relationship loading, and merged/cascading state are not implemented. |
| Flush, commit, and rollback | done | `tests/test_session_write.py` | `flush` compiles pending INSERTs, dirty-column UPDATEs, and DELETEs into one batched op list that crosses the FFI boundary once per flush (`NativeConnection.execute_flush`); `commit` flushes then commits; `rollback` rolls back and transitions unit-of-work state. Autoflush runs before `execute`, `scalars`, and `get` when enabled. |
| Savepoints | partial | — | `Session.begin_nested` delegates to `Connection.begin_nested` (see core/async matrices); full session-scoped savepoint transaction semantics remain deferred. |
