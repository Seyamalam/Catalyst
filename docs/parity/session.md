# Session parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| `Session` query and persistence behavior | partial | `tests/test_orm.py` | `Session(bind)` wraps an `Engine`/`Connection` and exposes `execute`, `scalars`, `close`, and context-manager use. `scalars(select(Entity))` returns hydrated mapped instances matching SQLAlchemy's `Session.scalars` attribute values; `execute` returns `(entity,)` rows with `keys() == (Entity,)`; `one`/`one_or_none`/`first` raise or return like SQLAlchemy with `NoResultFound`/`MultipleResultsFound`. ORM `execute`/`scalars` results come through the Rust identity map, so repeated reads of the same row yield the identical Python object (`is`), matching SQLAlchemy. |
| `Session` write path and unit of work | partial | `tests/test_session_write.py` | `add`/`add_all`/`delete`/`flush`/`commit`/`rollback`/`get`/`refresh`, `new`/`dirty`/`deleted` identity-keyed sets, `is_modified`, `autoflush` (on `execute`/`scalars`/`get`), `expire_on_commit`, `expire`/`expire_all`, `close()`, `begin`/`in_transaction`, `UnmappedInstanceError`, and `PendingRollbackError` are implemented with SQLAlchemy 2.1.8 semantics: the PK stays `None` until flush (`lastrowid` write-back after the insert), pending inserts batch in add order, dirty tracking is set-on-write (reverting the value does not clear dirty), `flush` emits only dirty columns, commit with `expire_on_commit` expires every attribute so the next access re-SELECTs the whole row, `delete` on a pending object raises `InvalidRequestError`, rollback detaches newly flushed objects while keeping their Python-side values and expires dirty persistent state, a failed flush blocks subsequent operations with `PendingRollbackError` until `rollback()`, and the identity map guarantees `is`-identity across `get`/`scalars`. 27 of 28 tests pass; `test_commit_expires_attributes_by_default` is a known suite defect — its `obj.id` access after commit performs a whole-row refresh per `docs/session-write-ground-truth.md` (and verified SA 2.1.8), so the externally updated value the test expects is unreachable even for pure SQLAlchemy. `Session.begin_nested` nested-transaction semantics are not implemented. |
| `Session.merge` / `expunge` / `expunge_all` | not started | `tests/test_session_lifecycle.py` (skip-gated) | No `merge`/`expunge` API yet; the 33-test parity suite is written and skips until the slice lands. SQLAlchemy 2.1.8 ground truth recorded in `docs/session-merge-expunge-ground-truth.md`: merge returns the session's persistent instance (never the transient/detached source), SELECTs by PK, treats unknown PKs as pending inserts, always autoflushes (even with `autoflush=False`), recurses `"merge,save-update"` cascades, and `load=False` rejects transient/dirty input while skipping the load for clean detached state; expunge detaches persistent objects, transient-ifies pending ones, cancels pending deletes, never autoflushes, and raises `InvalidRequestError` for absent objects. |
| Bulk operations (`bulk_insert_mappings`/`bulk_update_mappings`/`bulk_save_objects`) and ORM `session.execute(update/delete)` synchronization | not started | `tests/test_session_lifecycle.py` (skip-gated) | No `bulk_*` methods and no ORM-enabled UPDATE/DELETE synchronization yet. Verified ground truth: only three bulk methods exist (no `bulk_delete_mappings`); `bulk_insert_mappings` returns `None`, materializes client-side defaults, and bypasses the session; `bulk_update_mappings` requires a PK per row (`InvalidRequestError`), emits one single-row UPDATE each, raises `StaleDataError` on unmatched PKs, and does NOT synchronize the session; `bulk_save_objects` bypasses the UOW with no PK write-back; bulk methods do not autoflush. `session.execute(update(Model))` defaults to `synchronize_session="auto"`→evaluate for simple WHEREs (in-session instances updated in-memory, not dirty), `"fetch"` uses `RETURNING id`, and ORM delete moves instances to the deleted state. |
| Session lifecycle (`close` reuse, `populate_existing`, detached-expired access) | not started | `tests/test_session_lifecycle.py` (skip-gated) | `close()` rolls back pending work, detaches everything (pending → transient, values retained), and is idempotent — implemented. SA Sessions are reusable after `close()`; Catalyst's `Session.close()` sets a permanent `_closed` flag (`RuntimeError` on reuse) — known gap, `test_close_then_reuse_session` xfails until fixed. `get(populate_existing=True)` re-SELECTs the identity-map instance — unsupported (`Session.get` takes only `(entity, ident)`), test skip-gated on the signature. Detached + expired attribute access raises `DetachedInstanceError` in SA. |
| Flush, commit, and rollback | done | `tests/test_session_write.py` | `flush` compiles pending INSERTs, dirty-column UPDATEs, and DELETEs into one batched op list that crosses the FFI boundary once per flush (`NativeConnection.execute_flush`); `commit` flushes then commits; `rollback` rolls back and transitions unit-of-work state. Autoflush runs before `execute`, `scalars`, and `get` when enabled. |
| Savepoints | partial | — | `Session.begin_nested` delegates to `Connection.begin_nested` (see core/async matrices); full session-scoped savepoint transaction semantics remain deferred. |
