# Session parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| `Session` query and persistence behavior | partial | `tests/test_orm.py` | `Session(bind)` wraps an `Engine`/`Connection` and exposes `execute`, `scalars`, `close`, and context-manager use. `scalars(select(Entity))` returns hydrated mapped instances matching SQLAlchemy's `Session.scalars` attribute values; `execute` returns `(entity,)` rows with `keys() == (Entity,)`; `one`/`one_or_none`/`first` raise or return like SQLAlchemy with `NoResultFound`/`MultipleResultsFound`. ORM `execute`/`scalars` results come through the Rust identity map, so repeated reads of the same row yield the identical Python object (`is`), matching SQLAlchemy. |
| `Session` write path and unit of work | partial | `tests/test_session_write.py` | `add`/`add_all`/`delete`/`flush`/`commit`/`rollback`/`get`/`refresh`, `new`/`dirty`/`deleted` identity-keyed sets, `is_modified`, `autoflush` (on `execute`/`scalars`/`get`), `expire_on_commit`, `expire`/`expire_all`, `close()`, `begin`/`in_transaction`, `UnmappedInstanceError`, and `PendingRollbackError` are implemented with SQLAlchemy 2.1.8 semantics: the PK stays `None` until flush (`lastrowid` write-back after the insert), pending inserts batch in add order, dirty tracking is set-on-write (reverting the value does not clear dirty), `flush` emits only dirty columns, commit with `expire_on_commit` expires every attribute so the next access re-SELECTs the whole row, `delete` on a pending object raises `InvalidRequestError`, rollback detaches newly flushed objects while keeping their Python-side values and expires dirty persistent state, a failed flush blocks subsequent operations with `PendingRollbackError` until `rollback()`, and the identity map guarantees `is`-identity across `get`/`scalars` — all 28 tests pass (`test_commit_expires_attributes_by_default` was corrected to match verified SA 2.1.8 whole-row refresh semantics per `docs/session-write-ground-truth.md`). `Session.begin_nested` nested-transaction semantics are not implemented. |
| `Session.merge` / `expunge` / `expunge_all` | done | `tests/test_session_lifecycle.py` | `merge` returns the session's persistent instance (never the source), SELECTs by PK, treats unknown PKs as pending inserts, recurses `"merge"` relationship cascades, and honors `autoflush` — verified SA 2.1.8 merges flush pending work only when autoflush is enabled (the earlier "always autoflushes" claim in the ground-truth doc's derived notes was wrong: `Session.merge` calls `_autoflush()`, which no-ops under `autoflush=False`). `load=False` rejects transient objects and dirty objects whose identity is not already in the map (`InvalidRequestError`), merges clean detached objects without a SELECT into a persistent stub, and skips the `self.get` load entirely. `expunge`/`expunge_all` remove state + identity entries atomically in `NativeUow.detach`/`detach_all`, stamp a detached marker preserving pk/dirty/expired so `merge(load=False)` and re-`add` behave like SA, never autoflush, raise `InvalidRequestError` for absent objects, and leave pending objects transient and pending deletes' rows alive. |
| Bulk operations (`bulk_insert_mappings`/`bulk_update_mappings`/`bulk_save_objects`) and ORM `session.execute(update/delete)` synchronization | done | `tests/test_session_lifecycle.py` | Only the three SA methods exist (no `bulk_delete_mappings`). `bulk_insert_mappings` materializes client-side defaults and executemany-INSERTs bypassing the UOW (no PK write-back); `bulk_update_mappings` requires a PK per row (`InvalidRequestError`), emits one single-row UPDATE each, raises `StaleDataError` on unmatched PKs, and does not synchronize session state; `bulk_save_objects` INSERTs transient objects and UPDATEs persistent dirty ones (only dirty columns when `update_changed_only`) without touching the identity map; bulk methods do not autoflush. `session.execute(update(Model)/delete(Model))` keeps the mapped entity via `Update.entity`/`Delete.entity` + `execution_options(synchronize_session=...)`: `"auto"` (default) evaluates simple WHEREs in memory and falls back to `"fetch"`, `"evaluate"` rejects non-evaluable predicates with `InvalidRequestError`, `"fetch"` runs the statement plus `RETURNING <pk>` and syncs matched in-session instances in place (not marked dirty), `False`/`"false"` leaves the session stale, and delete moves matching instances to the deleted state so a subsequent `get` SELECTs and returns `None`. |
| Session lifecycle (`close` reuse, `populate_existing`, detached-expired access) | done | `tests/test_session_lifecycle.py` | `close()` rolls back pending work, detaches every object through `NativeUow.detach_all` (pending → transient, values retained), releases the owned connection, and is idempotent. Engine-bound sessions lazily re-acquire a connection on next use (matching SA's reusable-after-close contract); `Session(connection)` instances still cannot re-attach. `get(populate_existing=True)` re-SELECTs and refreshes the identity-map instance in place; ordinary `get` checks the identity map before autoflush so identity hits do not emit pending writes (SA `_get_impl` ordering). Expired attribute access re-SELECTs the whole row and raises `ObjectDeletedError` when the row is gone; detached expired column/relationship access raises `DetachedInstanceError`. |
| Flush, commit, and rollback | done | `tests/test_session_write.py` | `flush` compiles pending INSERTs, dirty-column UPDATEs, and DELETEs into one batched op list that crosses the FFI boundary once per flush (`NativeConnection.execute_flush`); `commit` flushes then commits; `rollback` rolls back and transitions unit-of-work state. Autoflush runs before `execute`, `scalars`, and `get` when enabled. |
| Session savepoints (`Session.begin_nested` / `SessionTransaction`) | done | `tests/test_savepoints.py` | `Session.begin_nested` returns a session-scoped `SessionTransaction` (`nested is True`, context-manager protocol); `Session.begin` returns the root `SessionTransaction` and raises `InvalidRequestError` on a second call. `commit()` emits `RELEASE SAVEPOINT` and folds the UOW snapshot frame into its parent; `rollback()` emits `ROLLBACK TO SAVEPOINT` (no RELEASE — matching SA's session savepoint emission) and restores the native `NativeUow` snapshot: objects pending or flushed inside the savepoint are expunged (out of `session.new` and the identity map — re-`add` works), dirty persistent objects are expired so the next access reloads pre-savepoint values and leave `session.dirty`, and flushed deletes resurrect to persistent. Nested savepoints stack; `with session.begin_nested():` releases on clean exit and rolls back on exception; releasing a savepoint then `session.rollback()` undoes everything once an outer transaction exists. Documented differences: Catalyst names savepoints `catalyst_sp_N` (SA: `sa_savepoint_N`, asserted SA-side only) and issues explicit `BEGIN` before the first savepoint, so SA's pysqlite first-savepoint RELEASE-commits gotcha does not reproduce (documented, not mirrored). The three-statement suite asserts the SA contract SQL-side plus Catalyst expunge/restore behavior. |
