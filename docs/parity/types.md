# Type parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| `Mapped[T]` and typed declarative columns | not started | — | Mapping API and inference tests are not implemented. |
| Accurate stubs for the native extension error API | partial | `python -m mypy.stubtest catalyst` | Error classes pass stubtest and strict type checks; no mapping or expression typing API exists. |
| SQLite Core column type bind/result processing | partial | `tests/test_types.py` | Integer, String, Text, Boolean, Float, Date, DateTime, bytes, NULL, malformed ISO results, timezone-offset results, and mismatched comparison literals are tested against in-memory SQLAlchemy SQLite. Malformed datetime result values, including a non-UTF-8 boundary after the date prefix, raise catchable Python `ValueError` with matching isoformat diagnostics (the parser uses checked UTF-8 slicing). SQLAlchemy-compatible SQLite storage formats are used (DateTime `YYYY-MM-DD HH:MM:SS.ffffff`; Date `YYYY-MM-DD`; bool 0/1); result columns are coerced by selected declared type. For directly stored timezone-bearing TEXT result values, DateTime reconstructs offsets with second-based `timedelta` values and matches SQLAlchemy; DateTime bind processing drops timezone information on storage, as SQLAlchemy does. DateTime accepts date values and stores midnight. Comparison literals only use a column's bind processor if compatible with that declared type; e.g. Boolean `== 2` and DateTime `== 5` bind raw values like SQLAlchemy. `Numeric`/Decimal is not supported: no Numeric marker/processor exists; raw Decimal binds are rejected with Catalyst `TypeError` rather than SQLAlchemy's wrapped `ProgrammingError`. Invalid typed datetime bind inputs likewise raise a direct type error rather than SQLAlchemy's wrapped `StatementError`. Typed Date/DateTime binds accept already formatted strings while SQLAlchemy rejects strings; this remains a parity gap. Boolean bind validation currently raises direct `TypeError` during compilation rather than SQLAlchemy's `StatementError(ValueError)` during execution. Corrupted/mismatched stored result values (e.g. nonnumeric Float text or text in a binary column) and lax date/datetime parsing edge differences are not fully aligned or exhaustively tested. Catalyst converts typed rows while buffering during execute whereas SQLAlchemy converts as rows are fetched. Type coercion currently applies to direct selected columns and Core binds, not arbitrary SQL result expressions or raw `text()` result columns. |
| PEP 681 `dataclass_transform` | not started | — | Declarative mapping is not implemented. |

Known difference: comparison bind processors are inferred from the Python literal type for date/datetime values, matching SQLAlchemy's value-based inference; type-mismatched result storage parsing has documented ISO-format edge differences (including lax zero-padding).
