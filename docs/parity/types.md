# Type parity matrix

| SQLAlchemy feature | Status | Proving test | Notes |
| --- | --- | --- | --- |
| `Mapped[T]` and typed declarative columns | partial | `tests/test_orm.py` | `DeclarativeBase`/`declarative_base()` map `Mapped[T]` annotations to Core `Table` columns with SQLAlchemy's type inference (`int`→`Integer`, `str`→`String`, `bool`→`Boolean`, `float`→`Double`, `datetime`→`DateTime`, `date`→`Date`, `bytes`→`LargeBinary`) and `Optional`/`X \| None` nullable inference, proven against identical SQLAlchemy mappings. `mapped_column` accepts positional name-or-type plus `primary_key`, `nullable`, `unique`, `default`, `default_factory`, `server_default`, `name`, `init`, `kw_only`. `select(Entity)` compiles identically to `select(entity.__table__)`; `insert`/`update`/`delete` accept mapped classes. Class attributes are `Column` objects at runtime, so `User.id == 1` builds Core expressions. Differences: `default=`/`default_factory=` also seed the generated `__init__` (SQLAlchemy's plain `DeclarativeBase` leaves unset attributes alone); non-`Mapped` annotations raise Catalyst `ArgumentError`; bare `mapped_column()` assignments map with Column-default nullable; relationships, inheritance, `MappedAsDataclass`, and imperative mapping are not implemented. |
| Accurate stubs for the native extension error API | partial | `python -m mypy.stubtest catalyst` | Error classes pass stubtest and strict type checks; no mapping or expression typing API exists. |
| `Double` column type | done | `tests/test_orm.py` | `Double` marker maps `float` annotation inference to SQLAlchemy's `DOUBLE`/`DOUBLE PRECISION` DDL per dialect (FLOAT for explicit `Float`) and shares float bind/result coercion. |
| SQLite Core column type bind/result processing | partial | `tests/test_types.py`, `tests/test_statement_error.py` | Integer, String, Text, Boolean, Float, Date, DateTime, bytes, NULL, malformed ISO results, timezone-offset results, and mismatched comparison literals are tested against in-memory SQLAlchemy SQLite. Malformed datetime result values, including a non-UTF-8 boundary after the date prefix, raise catchable Python `ValueError` with matching isoformat diagnostics (the parser uses checked UTF-8 slicing). SQLAlchemy-compatible SQLite storage formats are used (DateTime `YYYY-MM-DD HH:MM:SS.ffffff`; Date `YYYY-MM-DD`; bool 0/1); result columns are coerced by selected declared type. For directly stored timezone-bearing TEXT result values, DateTime reconstructs offsets with second-based `timedelta` values and matches SQLAlchemy; DateTime bind processing drops timezone information on storage, as SQLAlchemy does. DateTime accepts date values and stores midnight. Comparison literals only use a column's bind processor if compatible with that declared type; e.g. Boolean `== 2` and DateTime `== 5` bind raw values like SQLAlchemy. `Numeric`/Decimal is not supported: no Numeric marker/processor exists; raw Decimal binds raise `ProgrammingError` with `.orig`/`.statement`/`.params`, matching SQLAlchemy's driver-level error class. Invalid typed bind inputs (datetime strings, boolean values, unbindable objects) raise `StatementError` at execution — literal binds are deferred from compile to execute like SQLAlchemy — carrying `.orig`, `.statement`, and `.params` attributes. Typed Date/DateTime binds accept already formatted strings while SQLAlchemy rejects strings; this remains a parity gap. Corrupted/mismatched stored result values (e.g. nonnumeric Float text or text in a binary column) and lax date/datetime parsing edge differences are not fully aligned or exhaustively tested. Catalyst converts typed rows while buffering during execute whereas SQLAlchemy converts as rows are fetched. Type coercion currently applies to direct selected columns and Core binds, not arbitrary SQL result expressions or raw `text()` result columns. |
| PEP 681 `dataclass_transform` | done | `tests/test_orm_typing.py` | `DeclarativeBase` carries `@dataclass_transform(kw_only_default=True, field_specifiers=(MappedColumn, mapped_column))` (via `typing_extensions`, which `sqlalchemy.orm` also uses), so subclasses get a synthesized keyword-only `__init__`: `User(id="x")` fails mypy `--strict`, `User(id=1, name="a")` type-checks. `Mapped` is typed as a descriptor — instance access yields `T`, class access yields `Column` — and field `__init__` parameter types come from `Mapped.__set__`'s value type, matching or exceeding unplugin'd SQLAlchemy behavior. Field `default=`/`default_factory=` are honored as `__init__` defaults. |

Known difference: comparison bind processors are inferred from the Python literal type for date/datetime values, matching SQLAlchemy's value-based inference; type-mismatched result storage parsing has documented ISO-format edge differences (including lax zero-padding).
